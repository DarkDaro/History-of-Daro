## 1. Что это за сайт

Промо-сайт трилогии **«История Даро»** — антиутопия + постапокалипсис +
неонуар. Действие — 2147 год, город Хи-Мигата, семь корпораций, антигерой
Даро. Задача сайта: представить книги, дать читать фрагменты, держать
атмосферу мира.

Стиль зафиксирован и **удалению не подлежит**: boot-заставка, scanlines,
glitch, неон, бегущая строка (marquee), дождь, HUD-элементы. Это часть
идентичности сайта, а не украшательство.

Важно понимать: **сайт статический**. Сервера и базы данных у него нет.
На GitHub Pages лежат обычные `.html/.css/.js` файлы — как на сайтах из
эпохи «HTML руками», только сгенерированные компилятором.

## 3. Почему Next.js — объяснение для изучающего

Честный ответ: для промо-страницы хватило бы и голого HTML. Next.js взяли
ради четырёх конкретных выгод, каждая из которых решает реальную боль.

**Боль №1 — копипаста.** На чистом HTML шапку/футер правишь в каждом файле.
Здесь шапка описана один раз в `site-chrome.tsx` — и появляется на всех
страницах. Карточка книги — один компонент, а не три сверстанных блока.

**Боль №2 — правки скриптами.** Опыт с HTML+JS: чтобы поменять тексты или
структуру, писались десятки Python-скриптов, правящих файлы по регуляркам.
Здесь контент лежит в `content.ts` — правится руками, за один заход,
с проверкой типов: опечатался в имени поля — сборка упадёт и укажет место.

**Боль №3 — эффекты.** Глитч, неон, дождь, HUD — это React-компоненты с
`framer-motion` (библиотека анимаций). Руками на JS это сотни строк
одноразового кода, который страшно трогать.

**Боль №4 — служебные файлы.** RSS (`/feed.xml`), sitemap, канонические
ссылки, мета-теги для соцсетей, JSON-LD (разметка «это книга» для
поисковиков) — генерируются при сборке автоматически.

**Как это понимать в целом:** Next.js — это «фабрика». Исходники
(React-компоненты + `content.ts`) — сырьё. Команда `npm run build:static` —
запуск фабрики. Папка `out/` — готовая продукция: обычные HTML-файлы,
которые можно положить на любой хостинг. Фабрика нужна один раз — при
сборке; посетитель сайта получает чистую статику.

| Было (HTML руками) | Стало (Next.js) |
|---|---|
| Правка меню в 30 файлах | Правка в 1 файле + пересборка |
| Тексты размазаны по страницам | Один файл `content.ts` |
| Правки Python-скриптами по регуляркам | Правка руками, ошибки ловит сборка |
| RSS/sitemap руками или никак | Генерируются при сборке |
| Опасно рефакторить | Сборка упадёт и покажет, где сломали |

## 4. Два режима сборки и команды

| Команда | Что делает | Кому нужна |
|---|---|---|
| `npm run dev` | Живой просмотр на `localhost:3000`, правки видны сразу | Разработка |
| `npm run build:static` | Статика в `out/` — то, что на GitHub Pages | Публикация |
| `npm run build` | Standalone: самодостаточный Node-сервер (`.next/standalone/server.js`) | Запас на будущее (свой VPS) |
| `bash scripts/build-releases.sh` | Три архива (static/source/standalone) + manifest.json с sha256 | Раздача сборок |

Ключевой механизм — **basePath**. GitHub Pages живёт в подпапке
(`/History-of-Daro/`), локально сайт — в корне (`/`). Поэтому в коде пути
пишутся только через хелпер `asset()` из `content.ts`, а само значение
подставляется при сборке через переменную `NEXT_PUBLIC_BASE_PATH`. Одна
кодовая база работает и в подпапке, и в корне без правок.

## 5. Как работает автодеплой

```
git push в main
   → GitHub Actions запускает deploy.yml
      → npm install
      → вычислить basePath (по имени репозитория)
      → npm run build:static
      → touch out/.nojekyll   (чтобы GitHub не трогал статику Jekyll'ем)
      → configure-pages (enablement: true — включает Pages сам)
      → публикация артефакта
   ≈ через 3 минуты сайт обновлён
```

Адрес сайта: `https://darkdaro.github.io/History-of-Daro/`
Постоянные ссылки на архивы: `…/releases/daro-site-static.zip`,
`…/releases/daro-site-source.zip`, `…/releases/daro-site-standalone.zip`.
Страница загрузок: `…/download.html` (читает размеры и sha256 из
`releases/manifest.json`).

## 7. Философия правок: причинность, последовательность, откат

**Один коммит = одна причина.** Сообщение отвечает не только «что сделано»,
но и «почему». Это и есть документация, привязанная к коду.

**Точки возврата.** Перед значимыми изменениями ставится тег:
`git tag -a <имя> -m "<почему эта точка важна>"`. Список точек:

| Тег | Дата | Смысл |
|---|---|---|
| `meta-2026-11-01` | 2026-11-01 | Сайт работает на GitHub Pages; введён PROJECT-META; db.ts отключён |

**Рецепты отката** (от простого к жёсткому):

```bash
git log --oneline                 # посмотреть историю
git log -p src/lib/content.ts     # история одного файла

git reset --soft HEAD~1           # отменить последний коммит, файлы оставить
git revert <hash>                 # отменить конкретный коммит НОВЫМ коммитом
                                  # (безопасно, история не переписывается)
git checkout <hash> -- путь/файл  # вернуть один файл к состоянию коммита
git checkout <тег>                # «посмотреть» состояние на точке тега
git reset --hard <тег>            # ЖЁСТКИЙ откат ветки к точке тега

# если откатываемое уже запушено:
git revert <hash> && git push     # только так; force-push — исключение
git push --force-with-lease       # перезапись истории, безопаснее, чем -f
```

Правило: запушенная история не переписывается, кроме согласованных случаев
(например, перезапись авторов коммитов на хозяина — это был согласованный
force-push `d5a6273`).

- **Синопсис «Проекта Восход» — канон-тексты автора дословно** (2026-11-02):

## 9. Куда расти: формы, поиск, продающая страница

**Поиск по сайту — можно уже сейчас.** Статика не мешает: на этапе сборки
из `content.ts` генерируется `search-index.json` (книги, фрагменты,
персонажи, корпорации), на клиенте — библиотека Fuse.js или MiniSearch,
интерфейс — палитра `Ctrl+K` в стиле терминала. Работает на GitHub Pages
без всякого сервера. **Статус: сделано 2026-11-01** — палитра Ctrl+K на
Fuse.js, индекс собирается на сборке (коммит `084fe00`); сам индекс живёт
в клиентском бандле, а не отдельным json — на Pages надёжнее.

**Формы без бекенда.** Статика сама не принимает данные — подключаем
готовые сервисы, код формы лежит прямо на странице. **Статус: по решению
хозяина (2026-11-01) форма подписки остаётся честной заглушкой до
публикации сайта** — приёмник (Formspree и т.п.) не регистрировать;
механика подключения уже вшита (см. п. 8, decision log).

- «Уведомить о выходе книги» / подписка — Formspree или Web3Forms (POST
  на их endpoint), либо рассылка Buttondown/Mailchimp;
- обратная связь автору — то же, плюс простейший `mailto:`;
- комментарии читателей — giscus: комментарии хранятся в Discussions
  нашего же GitHub-репозитория, бесплатно, без сервера;
- опросы — Google Forms / StrawPoll встраиванием.

**Продающая страница — да, это естественный следующий шаг.** Технически
это те же статические страницы, меняется композиция: оффер в первом
экране → обложки трёх томов → фрагменты-крючки («читать первый эпизод»)
→ цитаты/отзывы → форматы и цены (электронная/печатная/аудио) → FAQ →
кнопка. Приём денег статикой не делается — кнопки «Купить» ведут на
площадки (Литрес, Ozon, Amazon…) или сервисы типа Gumroad/Boosty, а форма
«уведомить меня» ловит тех, кто купит позже. Архитектуру менять не нужно.

## 10. Глоссарий

- **React** — библиотека интерфейсов; страница собирается из компонентов.
- **Компонент** — переиспользуемый блок (шапка, карточка книги), описан
  один раз, используется много где.
- **Next.js** — фреймворк над React: роутинг по папкам, сборка, оптимизации.
- **Сборка (build)** — превращение исходников в готовые HTML/CSS/JS.
- **Статический экспорт** — режим сборки «только файлы, без сервера».
- **Standalone** — режим сборки «Node-сервер в одной папке».
- **basePath** — префикс адреса (`/History-of-Daro/`), под которым живёт
  сайт на GitHub Pages.
- **Хук `asset()`** — наш хелпер: прибавляет basePath к путям картинок/ссылок.
- **Prisma / ORM** — прослойка для работы с настоящей БД (у нас отключена).
- **git revert / reset / tag** — отмена коммитом / перемещение ветки /
  метка-точка возврата.
- **GitHub Actions / workflow** — скрипты, которые GitHub запускает сам
  (у нас: сборка и публикация при каждом push).
- **GitHub Pages** — бесплатный хостинг статики из репозитория.
- **sha256** — отпечаток файла для проверки целостности.

## 11. Аудио-система (состояние на 2026-11-01)

Всё аудио синтезируется на Web Audio API — внешних файлов нет, вес — ноль
байт. Включается кнопкой «Эфир» в шапке; флаг и настройки живут в
localStorage.

### Как устроено сейчас

| Файл | Роль |
|---|---|
| `src/lib/sfx.ts` | Звуки интерфейса: hover, click, confirm, deny, boot, whoosh. Осцилляторы (sine/triangle/sawtooth) с огибающими + шумовые всплески через bandpass. Троттлинг hover — 90 мс |
| `src/components/ambient-audio.tsx` | Кнопка «Эфир» (3 состояния: OFF / «оживёт при первом жесте» / играет) + генеративный эмбиент из 5 слоёв: дождь (белый шум → lowpass 1500 Гц + медленная модуляция), hiss 4.2 кГц, дрон 55/110 Гц, пэд-аккорд A2·E3·A3·C4, суб-пульс 27.5 Гц, случайный гром раз в 16–38 с |

Включение: флаг «Эфир» в `daro-ether`; если с прошлого визита «on», старт
откладывается до первого жеста (pointerdown/keydown) — требование браузеров
к автозапуску звука. SFX привязаны к тому же флагу. При выключении —
плавный fade-out 0.7 с, затем очистка узлов.

### Известные ограничения (основа плана — см. ROADMAP.md)

1. **Два независимых AudioContext** — sfx.ts и ambient-audio.tsx друг о
   друге не знают: общая громкость технически невозможна.
2. **Дождь = белый шум** через lowpass — звучит как шипение вентилятора,
   а не дождь.
3. **Нет регулировки громкости** — только вкл/выкл; гейны зашиты в код
   (0.85 master, фиксированные уровни слоёв и SFX).
4. **Одна тема на весь сайт** — эмбиент одинаков на всех страницах.
5. **SFX покрывают не всё** — нет звуков глитча, печати терминала,
   перехода между страницами, открытия палитры поиска.

### Состояние ПОСЛЕ блока A (2026-11-01, ROADMAP A1–A5 выполнены)

Все пять ограничений выше сняты:

- **Одно ядро** (`audio-engine.ts`): один AudioContext, шины
  `master → {ambience, music, ui}`; громкости в localStorage
  (`daro-vol-master`, `-ambience`, `-music`, `-ui`), меняются плавно.
- **Микшер**: у кнопки «Эфир» вторая мини-кнопка — попап с ползунками
  «Общая / Дождь и город / Темы страниц / Интерфейс» (A2).
- **Дождь**: розовый шум (фильтр Келлета, стерео-база) + случайные
  капли (bandpass 1.2–4 кГц, 7–18/с) + редкие «желобные» капли; гром
  сохранён (A3).
- **Темы страниц** (`audio-themes.ts`): у каждого раздела своя
  генеративная тема на шине «music» (9 ладов: дом, книги, мир,
  персонажи-нуар, читалка, таймлайн-секвенсор, техника, архив,
  нейтральная); смена — кроссфейд ~1.2 с по pathname (A4).
- **SFX 12 видов**: + glitch, type (троттлинг 45 мс), transition
  (смена страницы), palette (Ctrl+K), open/close (досье) (A5).
- Контекст больше не закрывается при выключении «Эфира» — он общий.
- Гайд по расширению аудио — не нужен: все параметры тем в одной
  таблице `THEMES` в audio-themes.ts.
