# CI-gates — проверки и верификация

Главный принцип, набитый ошибками:

> **«Скрипт прошёл» ≠ «сайт выглядит правильно».**
> Сборка проходит и с кривым сайтом. После каждой правки сайт
> проверяется скриптами (ловят то, что глаз пропустит) и глазами
> (ловят то, что скрипт не видит). Гейт в CI ломает деплой ДО
> публикации — битое не доезжает до продакшена.

---

## 1. Обязательный пайплайн перед коммитом

```bash
node scripts/check-links.mjs      # ссылки, якоря, картинки
python3 scripts/check-slop.py .   # стоп-лист, плейсхолдеры, следы
```

- Для правок только `*.md` (метафайлы, правила) — пайплайн не нужен.
- Всё подсветившееся чинится ДО коммита, а не «поправлю потом».
- Пайплайн фиксирован и не обсуждается на ходу: менять его —
  отдельный чанк `инфра:`.

## 2. Что проверяют скрипты (и почему именно это)

| Проверка | Ловит | Инструмент |
|---|---|---|
| Внутренние ссылки, якоря, картинки | «404 после деплоя», битые `src` после переименований | `scripts/check-links.mjs` |
| Стоп-лист слопа, плейсхолдеры, следы генерации | ИИ-штампы, забытые TODO/`【…】` | `scripts/check-slop.py` |
| Отдача страниц | пустые/сломанные файлы | локальный сервер + `curl` |
| Горизонтальный overflow | уехавшая вёрстка на узких экранах | headless-браузер, ширины 360/390/768/1024/1280 |
| Доступность (минимум) | контраст, alt, иерархия заголовков, тап-цели ≥ 44 px | ручной чек-лист; при наличии node — axe-core |
| Валидность HTML | незакрытые теги после ручной правки разметки | validator.w3.org/nu/?url=… выборочно |

Скрипты комплекта — **без зависимостей** (plain node / python3):
линтер, который требует установки окружения, не запускается «прямо
сейчас», а значит не запускается никогда.

Служебные тексты по умолчанию не сканируются: каталоги `.git`,
`node_modules`, `out`, `.github`, `scripts`, `rules`, `vendor` и
метафайлы `AGENTS.md`/`PROJECT-META.md`/`SESSIONS.md`/`BACKLOG.md` —
они рассказывают О правилах и цитируют стоп-лист, поэтому их находки —
шум. Проверить их осознанно: `check-slop.py . --keep-meta`.

## 3. Локальная живая проверка

```bash
python3 -m http.server 8000 --directory out
# в другом терминале:
for p in / /about /gallery; do curl -s -o /dev/null -w "%{http_code} $p\n" http://localhost:8000$p; done
```

Все проверенные маршруты — 200; ключевые страницы открываются глазами:
шапка, футер, изображения, шрифты, консоль браузера без ошибок.

## 4. Гейт в CI

`.github/workflows/deploy-pages.yml` (готовый — в `examples/`):

1. чек-аут репозитория;
2. гейты: `check-links.mjs` + `check-slop.py` — падение ломает деплой;
3. сборка чистой копии сайта в `out/` (исключения служебных папок
   зашиты явно — это и защита от утечки `rules/`, `scripts/` на прод);
4. публикация `out/` на GitHub Pages.

## 5. После пуша

1. Проверить CI по SHA (`gh run list` или API check-runs); первый
   ответ часто `pending` → пауза 45–75 секунд, повтор. Красный CI =
   чанк не закрыт, следующий чанк не начинается.
2. **Живая сверка прода.** Открыть опубликованный сайт, проверить
   именно то, что менялось, плюс дым: главная, одна внутренняя,
   картинка, консоль. «Запушил — значит работает» не считается.
3. Инцидент деплоя (упало, уехало криво) фиксируется в SESSIONS
   с причиной и рецептом отката — тогда это последний такой инцидент.

## 6. Визуальная проверка (для вёрстки и дизайна)

- Скриншоты узких мест на 5 ширинах (360/390/768/1024/1280):
  шапка, сетки, длинные слова, таблицы.
- Смотрится именно рендер, не код: `overflow-x` на body, слипшиеся
  отступы, обрезанный текст, «пляшущие» базовые линии.
- Эталон мобильного — реальный телефон, а не только эмулятор.
- `prefers-reduced-motion` уважается: анимации не обязательны,
  читаемость обязательна.
