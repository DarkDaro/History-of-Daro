# CLUB-DESIGN.md — проект клуба «Истории Даро» (вариант А)

> Решение автора 2026-11-27: вариант А — Boosty принимает деньги,
> сайт остаётся витриной, клуб пускает и бесплатных, и платных.
> Без ИП, без собственной кассы, без паролей.
> Статус документа: проект. Код не начат; макет страниц — вне репо
> (`download/club-mockup.html`, песочница), в прод не собирается.
> Каждая строка «решить позже» разблокируется явной командой автора.

## 1. Что решено

| Вопрос | Решение |
| --- | --- |
| Деньги | Boosty: касса, уровни, чеки, отмены — всё на платформе |
| Полный текст романа | Boosty, закрытые посты по уровням |
| Витрина | Остатётся статикой на GitHub Pages, бекенд туда не возвращается |

| Демо-том | Расширение `/excerpts`, без бекенда |

## 2. Роли и вход («пропуск»)

Принцип: хранить и шифровать пароли не нужно, потому что паролей нет.
Вход — одноразовый код письмом, повышение уровня — пропуск из Boosty.

Поток входа:

1. Участник вводит email на `/club`.
2. Сервер шлёт одноразовый код (6 цифр, живёт 10 минут, хранится хэшем).
3. Участник вводит код — создается запись `Member` или находится старая,
   выдаётся подписанная сессия-cookie. Уровень по умолчанию — «Гость».
4. Boosty-пропуск (код вида `ПЕРИМ-XXXX`) вводится в кабинете: код
   привязывается к email, уровень повышается. Один код — один участник.
5. Отмена подписки: автор отзывает пропуск вручную (пока — SQL,
   админ-страница после первых участников, см. раздел 6).

Механика выдачи пропусков на Boosty: в закрытом посте каждого уровня
лежит код. Утечка или смена — автор правит пост, старый код отзывается
запросом в БД. Когда участников станет больше ~30 — пул одноразовых
кодов (таблица `Pass` уже под это спроектирована).

## 3. Уровни поддержки — каркас выгод

Каждый уровень включает всё предыдущего. Цены — ориентир для старта,
финальные значения называет автор при настройке Boosty (платформа
позволяет любую цену и ежемесячное списание).

| Уровень | Что даёт | Ориентир цены |
| --- | --- | --- |
| Гость (бесплатно) | Читать ленту Q&A, демо-том на витрине, RSS, 1 вопрос в месяц в общей очереди | 0 ₽ |
| Уровень 1 | Приоритет в очереди вопросов, голос за тему очередного разбора мира, ранние анонсы глав | ~100 ₽/мес |
| Уровень 2 | Вопросы без месячного лимита, полный текст романа в Boosty (закрытые посты по главам) | ~300 ₽/мес |
| Уровень 3 | Вопрос вне очереди (ответ в течение недели), имя в благодарностях тома, раз в месяц — выбор темы хронологии | ~700 ₽/мес |

Названия уровней — три набора из мира цикла, выбор за автором:

| Набор | Уровень 1 | Уровень 2 | Уровень 3 | Отсылка |
| --- | --- | --- | --- | --- |
| А | Слушающий | Связной | Периметр | «Периметр Зеро» — сопротивление |
| Б | Приёмник | Частота | Эфир | Эмбиент «Эфир» и радиообразы сайта |
| В | Стажёр баланса | Актив | Вне баланса | Даро — «актив, ушедший с баланса» |

## 4. Схема данных (эскиз Prisma)

База — Postgres на Vercel/Neon либо SQLite на VPS: схема одинаковая,
`datasource` меняется одной строкой. Шаблонные модели `User`/`Post`
из `prisma/schema.prisma` заменяются при первом чанке — по правилу
«не удалять напрямую»: старый текст выводится в комментарий журнала.

```prisma
model Member {
  id         String    @id @default(cuid())
  email      String    @unique
  callsign   String?   // позывной в клубе, виден в ленте
  level      String    @default("guest") // guest | l1 | l2 | l3
  createdAt  DateTime  @default(now())
  lastSeenAt DateTime?
  questions  Question[]
}

model Pass {
  id         String    @id @default(cuid())
  code       String    @unique // ПЕРИМ-XXXX
  level      String    // l1 | l2 | l3
  memberId   String?   // кто активировал
  member     Member?   @relation(fields: [memberId], references: [id])
  issuedAt   DateTime  @default(now())
  activatedAt DateTime?
  revokedAt  DateTime? // отзыв при отмене подписки
  note       String?   // «утечка — перевыпуск 2026-12-05»
}

model Question {
  id        String    @id @default(cuid())
  memberId  String
  member    Member    @relation(fields: [memberId], references: [id])
  body      String    // текст вопроса, до 2000 символов
  status    String    @default("queued") // queued | answered | withdrawn
  createdAt DateTime  @default(now())
  answers   Answer[]
}

model Answer {
  id         String   @id @default(cuid())
  questionId String
  question   Question @relation(fields: [questionId], references: [id])
  body       String
  publishedAt DateTime @default(now())
}

model Feedback {
  id        String   @id @default(cuid())
  name      String?  // имя, необязательно
  email     String   // без ответа не бывает — email обязателен
  body      String
  createdAt DateTime @default(now())
  status    String   @default("new") // new | read
}

model ChapterMeta {
  id      String  @id @default(cuid())
  volume  Int     // том 1..3
  number  Int     // номер главы в томе
  title   String
  status  String  // draft | on-boosty | published
  body    String? // резерв: хранить ли текст глав на сайте — решение автора «решить позже»
}
```

Очередь вопросов: сортировка `level 3 → level 2 → level 1 → guest`,
внутри уровня — по времени. Лимиты на стороне приложения, не в схеме.

## 5. Страницы клуба

| Маршрут | Блоки | Поведение |
| --- | --- | --- |
| `/club` | Вход: email → код; поле «есть пропуск Boosty?» | Без сессии доступен только этот маршрут и `/club/feedback` |
| `/club/qa` | Лента вопросов со статусами (В ОЧЕРЕДИ / ОТВЕЧЕНО / СНЯТО), форма вопроса с лимитом уровня | Вопрос видят все участники, пишет ответ только автор; ответы автора — от его имени без «дискуссий» |
| `/club/me` | Кабинет: карточка уровня, статус пропуска, мои вопросы, поле активации пропуска, выход | Активация пропуска повышает уровень сразу |
| `/club/feedback` | Форма: имя (опц.), email, текст | Доступна без входа; пишет в `Feedback`, письмо-уведомление автору |

Оформление — та же система сайта: неоновая палитра, HUD-рамки,
Russo One / Play / JetBrains Mono, эффекты из `src/components/cyber`.
Клуб помечается в шапке сайта отдельным пунктом навигации, ссылка
ведёт на адрес клуб-приложения.

## 6. Админ-минимум

До первых 10 участников админ-операции выполняются SQL-запросами
(ответ на вопрос, отзыв пропуска, отметка письма прочитанным):
запросы хранятся в этом документе, раздел пополняется по мере
появления операций. Админ-страница `/club/admin` (вход только с
email автора) — отдельный чанк после первых участников.

## 7. Демо-том на витрине

`/excerpts` дополняется маршрутом «Демо-том»: подборка фрагментов,
расставленных как маршрут чтения первой главы, плюс блок
«Полный текст — на Boosty» со ссылкой на блог. Контент — модуль в
`src/content/`, сборка остаётся статической, бекенд не нужен.
То, что участник платного уровня читает главы в Boosty, а гость —
демо-том на витрине, и есть воронка без единой строки платёжного кода.

## 8. Хостинг и внешние зависимости

| Слой | Вариант 1 | Вариант 2 |
| --- | --- | --- |
| Приложение | Vercel Hobby (0 ₽; по правилам платформы — некоммерческое использование, клуб на Boosty-кассе в серой зоне; осознанный риск) | VPS в РФ (Timeweb/Selectel, оплата СБП/МИР; тот же standalone + Caddyfile уже в репо) |
| База | Postgres: Neon или Supabase, бесплатные планы | SQLite в файле на VPS |
| Письма | Resend, бесплатный лимит ~100 писем/сутки (уточнить при подключении) | SMTP своего домена |

Fallback входа: если почтовая интеграция не взлетит, клуб пускает
только по Boosty-пропуску — бесплатных участников тогда автор вносит
вручную тем же SQL-минимумом. Схема и страницы не меняются.

Доступность из РФ: Vercel открывается; при блокировках переезд на
VPS — смена двух переменных окружения, схема та же.

## 9. План автора на Boosty (вне кода)

1. Завести аккаунт, оформить блог «История Даро» (шапка, описание,
   обложка — переиспользовать OG-картинки сайта).
2. Создать три уровня: названия из раздела 3, цены автор определяет.
3. В закрытый пост каждого уровня положить код-пропуск (`ПЕРИМ-XXXX`).
4. Welcome-сообщение подписчику: как войти в клуб (адрес, два шага).
5. Полный текст романа: закрытые посты по главам, уровень 2 и выше;
   открытые посты — анонсы и свободные главы для уровня 1.

## 10. Этапы внедрения (чанки)

| № | Чанк | Проверки |
| --- | --- | --- |
| 1 | Схема Prisma, замена шаблона User/Post, миграции на пустой БД | `prisma migrate dev`, lint, tsc |
| 2 | Вход по email-коду (`/club`) | ручной прогон + смоук API |
| 3 | Пропуска и кабинет (`/club/me`) | ручной прогон: активация, отзыв, смена уровня |
| 4 | Лента Q&A (`/club/qa`) | ручной прогон: лимиты уровней, очередь, статусы |
| 5 | Обратная связь (`/club/feedback`) | honeypot-тест, лимит с IP, письмо-уведомление |
| 6 | Демо-том на витрине | `build:static`, check-content, smoke |

Витринные чанки (6) идут через стандартный пайплайн репозитория;
клубные (1–5) — полная сборка и деплой клуб-приложения. Статический
экспорт исключает `/club/*` из `out/` той же механикой, что уже
используется для `releases/` и `download.html` в `scripts/build-static.mjs`.

## 11. Риски

- Vercel Hobby формально некоммерческий. Клуб не проводит платежи
  через сайт (касса — Boosty), но если понадобится чистота — VPS,
  перенос описан в разделе 8.
- Код уровня может утечь. Цена утечки: чужой вход под чужим уровнем;
  лечение — перевыпуск за минуту. При росте клуба — пул одноразовых
  кодов.
- Бесплатные лимиты (Resend, Neon) конечны: при росте до сотен
  участников — платный план или переезд на SMTP/VPS.
- Один код на уровень не даёт статистики по участникам Boosty —
  кто именно подписан, видно только в Boosty. Для клуба этого
  достаточно; связь «email ↔ подписка» устанавливает сам участник,
  активируя пропуск.

## 12. Возврат и отключение

Клуб — новые маршруты и файлы, существующие не тронуты: витрина
собирается и живёт как раньше. Отключение клуба — убрать `/club/*`
из исключений статического экспорта и перестать деплоить полную
сборку; схема Prisma и этот документ остаются в репо как проект
с путём возврата. Удаление — только отдельным чанком с причиной.

## 13. Деплой (двухфазный, отложен)

Фаза 1 — сейчас: витрина на GitHub Pages, статический экспорт,
CI собирает и выкладывает. Клуб в этой фазе не деплоится.

Фаза 2 — вместе с бэкендом (BACKEND-PLAN.md, чанк Б-7): VPS и
Coolify (self-hosted, без подписки): Docker-сборка полной версии
сайта с /club/*, SQLite в volume, секреты в env, Traefik +
Let's Encrypt, cron-дамп SQLite в бэкапы. Хостинг и лимиты —
раздел 8, механика — DEPLOY.md. Старт фазы 2 — по явной команде
автора; до неё ничего не меняется.
