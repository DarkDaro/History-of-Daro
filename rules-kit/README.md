# Rules Kit — правила ведения проекта

Набор правил, выработанных в ходе работы над промо-сайтом
«История Даро» (Next.js → GitHub Pages, 2026-11) и перенесённых
сюда для нового проекта: **статичный сайт на чистом HTML/CSS/JS
без сборщика, редизайн со сохранением контента, хостинг — GitHub Pages**.

Цель комплекта: чтобы работа велась предсказуемо, сайт не зарастал
ИИ-слопом и следами генерации, а история репозитория читалась
как журнал решений, а не свалка «wip».

---

## Состав

| Файл | Что внутри | Когда читать |
|---|---|---|
| `AGENTS.md` | Точка входа для ИИ-агента: свод в 20 строк | Кладётся в корень нового репо |
| `anti-slop.md` | Как писать тексты и UI-копирайт без ИИ-слопа; стоп-лист | Перед любой правкой текста |
| `no-traces.md` | Гигиена: не оставлять следов генерации в коде, репо, деплое | Постоянно; при настройке репо — целиком |
| `commits.md` | Стиль коммитов и git-дисциплина | Перед каждым коммитом |
| `ci-gates.md` | Проверки: что гонять после каждой правки + готовые скрипты | После каждой правки; при настройке CI — целиком |
| `workflow.md` | Цикл работы и сессии, метафайлы, порядок редизайна | В начале каждой сессии |
| `scripts/check-links.mjs` | Готовый линтер внутренних ссылок/картинок (plain node) | В `scripts/` нового репо |
| `scripts/check-slop.py` | Готовый линтер текстов: стоп-лист + плейсхолдеры (python3) | В `scripts/` нового репо |
| `examples/deploy-pages.yml` | GitHub Actions: гейты → автодеплой Pages | В `.github/workflows/` нового репо |

## Как подключить

1. Скопируй `rules/` в корень нового репозитория, скрипты — в `scripts/`,
   workflow — в `.github/workflows/`.
2. В корень положи `AGENTS.md` (из комплекта). Любой ИИ-агент
   (Claude Code, Copilot, Z.ai) читает его первым и дальше идёт
   по ссылкам на конкретный файл правила.
3. Первый коммит нового репо: `инфра: правила проекта — rules/, скрипты проверок, деплой Pages`.

## Два принципа, на которых держится всё

1. **«Скрипт прошёл» ≠ «сайт выглядит правильно».** После каждой правки
   сайт проверяется скриптами и глазами (рендер/живой сайт). Красный
   гейт ломает деплой ДО публикации — битое не доезжает до продакшена.
2. **GitHub — источник истины.** 1 коммит = 1 причина, пуш сразу после
   зелёного пайплайна, force-push запрещён. Перед работой — `git fetch`
   и сверка с `origin/main` (рабочие копии и песочницы теряют память;
   сервер — никогда).

## Откуда правила

Выжато из реальной практики: паспорт принципов PROJECT-META §16,
гайд текстов CONTENT.md (деталь вместо объяснения, стоп-лист), линтер
контента в CI, журналы SESSIONS/BACKLOG и разборы инцидентов (автокоммит
с UUID, рассинхрон снапшотов песочницы). Общие места помечены, конкретика
Даро обобщена под стек-агностичный статик-сайт.
