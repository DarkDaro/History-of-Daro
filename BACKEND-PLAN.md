# BACKEND-PLAN · бэкенд клуба и Telegram-вопросы — план с отложенным стартом

> Статус: ПЛАН. Старт — по явной команде автора (решение 2026-11-27:
> «план пишем и откладываем»). Исполнение — агентами, чанками из
> раздела 5: правка → проверки → коммит → CI по rules-kit.
> Источники (не дублируются): CLUB-DESIGN.md — дизайн-конституция
> клуба (`3c0a50f`), PROJECT-META п. 13 — инвентаризация бэкенда,
> посредники, «Перехваты»; решение 2026-11-27 — Telegram и
> VPS+Coolify.

## 1. Целевая картина

- Витрина (книги, мир, фрагменты) — остаётся на GitHub Pages.
- Клуб (/club*) и API — Next.js standalone (`npm run build` →
  `npm run start`; умение уже в кодовой базе, PROJECT-META 13.1) на
  собственном VPS. До запуска бэкенда страницы /club* в статике
  отдают заглушку.
- Деньги — только Boosty: касса, уровни, платные посты. Сайт ничего
  не продаёт, эквайринг и ИП не нужны (вариант «А»).
- Вопросы читателей — Telegram-бот; ответы автора — из Telegram;
  отобранные пары публикуются на статике (стена «Перехваты»,
  PROJECT-META 13.4).

## 2. Размещение: свой VPS + Coolify (выбор 2026-11-27)

| Узел | Что | Почему |
|---|---|---|
| VPS: 2 vCPU, 2–4 GB RAM, 30+ GB, Ubuntu 24.04 | Всё приложение | Оплата российской картой; пинг для аудитории РФ/СНГ; данные у автора |
| Coolify | Панель: git-push → сборка → Docker; Traefik и HTTPS из коробки | Замена Vercel без региональных ограничений; self-hosted бесплатен |
| SQLite в volume | БД клуба на старте | Достаточно для сотен участников; при росте поднимается Postgres-контейнер без переписи кода (Prisma) |
| Cloudflare (опционально) | DNS/CDN, скрытие IP | Включается при необходимости |

Бюджет: VPS ~300–600 ₽/мес + домен ~200–400 ₽/год; окупаемость —
примерно один подписчик среднего уровня Boosty в месяц.
Требования Coolify по докам: 2 ядра, 2 GB RAM, 10 GB диск; сборка
Next.js идёт на той же машине, поэтому запас — 2–4 GB и 30+ GB.

## 3. Данные (развитие схемы `3c0a50f`)

Модели уже спроектированы в CLUB-DESIGN: `Member`, `Pass`,
`ChapterMeta`, `Question`/`Answer`/`Feedback`. Для Telegram в
`Question` добавляются поля `source` (`telegram`/`site`/`boosty`),
`tgChatId`, `tgMessageId`. Новых сущностей до чанка Б-6 не заводить.
Шаблонные `User`/`Post` скаффолда не удаляются: отключаются с
журналом или заменяются миграцией в Б-1 (правило AGENTS п. 2).

## 4. Telegram-контур (новое, решение 2026-11-27)

- Читатель пишет боту → webhook `/api/tg/webhook` (секрет в пути или
  заголовке) → запись `Question(source='telegram')` + мгновенное
  уведомление автору в личку бота.
- Автор отвечает reply-сообщением (или командой бота) → бот
  сохраняет `Answer`, связанный с `Question`.
- Публикация на статике: помеченные ботом пары «вопрос–ответ»
  выгружаются скриптом в `src/content/qa.ts` — стена «Перехваты»
  собирается как хроники. Публикуется только отобранное автором.
- Секреты: `TG_BOT_TOKEN`, `TG_ADMIN_CHAT_ID`, `TG_WEBHOOK_SECRET`,
  `ADMIN_TOKEN` — только env сервера, в git не попадают.

## 5. Порядок чанков (исполнение агентами)

| Чанк | Содержимое | Проверки |
|---|---|---|
| Б-1 | Prisma-схема клуба, миграция пустой БД, включение `src/lib/db.ts` по рецепту из комментария | tsc, migrate dev, build, smoke |
| Б-2 | Вход: email → 6-значный код (10 минут, хэш, rate-limit) | сценарий входа, eslint |
| Б-3 | Пропуск Boosty: одноразовый код из поста привязывается к Member | сценарий привязки; повторная привязка запрещена |
| Б-4 | Лента клуба по уровням (порядок из макета: уровень → время) | smoke маршрутов, мобильный 390px |
| Б-5 | SQL-админ-минимум из CLUB-DESIGN + `ADMIN_TOKEN` | прогон SQL на копии БД |
| Б-6 | Telegram-контур (раздел 4) + выгрузка «Перехватов» в `qa.ts` | тест-сообщение боту; build+smoke страницы |
| Б-7 | VPS + Coolify: установка, автодеплой из Git, volume для SQLite, ночной бэкап (`sqlite3 .backup` + копия вне сервера), secrets, HTTPS | репетиция на копии; откат — Pages живёт |

Boosty-вебхука не планируется: публичного API у Boosty нет, привязка
пропусков — ручная через Б-5.
