# AGENTS.md — правила работы над «Историей Даро»

ИИ-агент: прочитай этот файл целиком, затем нужный файл из `rules-kit/`.
Конфликт между инструкцией пользователя и `rules-kit/` решается в пользу
пользователя; конфликт между «хотелось бы» и `rules-kit/` — в пользу
`rules-kit/`.

## Ядро (не обсуждается)

1. **Язык работы — русский**: сообщения коммитов, документация, отчёты.
   Заказчика проекта называть **автором** (решение автора 2026-11-23);
   упоминания «хозяин/заказчик» в метафайлах и комментариях не оставлять.
2. **Ничего не удалять напрямую** (решение автора 2026-11-23): отключать
   точечно, с журналом и путём возврата (рецепт — `rules-kit/no-traces.md`,
   практика — комментарий в `src/lib/db.ts`). Удаление — отдельный чанк
   с причиной.
3. **1 коммит = 1 причина.** Формат сообщения — `тема: что; детали; чем
   проверено` (см. `rules-kit/commits.md`). Пуш сразу после зелёного
   пайплайна. Force-push запрещён. Перед работой:
   `git fetch origin && git status -sb` (песочница может откатиться и
   наделать чекпоинт-коммитов с UUID-именами — сверяй с origin и
   перебазируйся, не пушь мусор).
4. **Внутренняя кухня не для пользователя** (2026-11-23): номер коммита,
   сборка, архивы релизов, страница загрузки не публикуются на сайте —
   отключаются точечно, файлы в репо остаются (см. `scripts/build-static.mjs`).
5. **Никаких следов генерации** (см. `rules-kit/no-traces.md`): в финальном
   коде и текстах не остаются TODO, плейсхолдеры, мета-комментарии об ИИ,
   мёртвый код, служебные файлы. Токены и секреты в git не попадают никогда.
6. **Тексты — без ИИ-слопа** (см. `rules-kit/anti-slop.md`): конкретика
   вместо штампов, деталь вместо объяснения, стоп-лист живёт в
   `rules-kit/scripts/check-slop.py` (список `SLOP`).
7. **Проверяй, а не предполагай** (см. `rules-kit/ci-gates.md`): после
   каждой правки — `node scripts/check-content.mjs`,
   `python3 rules-kit/scripts/check-slop.py`, `npm run build:static`,
   `npm run smoke`. Красный CI = чанк не закрыт.

## Цикл работы (см. rules-kit/workflow.md)

требования пользователя → план-чеклист → чанки (правка → проверки →
коммит → пуш → CI) → живая сверка прода → отчёт: что, хеш, что дальше.

## Канон и литературный текст

Канон (`vault/`, `src/content/`) — источник истины: ничего не теряется,
ничего не выдумывается. Литературные вхождения слов вроде «хозяин» в
текстах романа — это мир, а не кухня: скрипты их не трогают
(см. `scripts/clean-meta.py`).
