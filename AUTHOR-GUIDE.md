# Кулинарная книга автора «Истории Даро»

> Задача этого документа: чтобы ТЫ сам, без программиста, добавлял
> персонажей, корпорации, импланты, фрагменты и главы — и сайт
> продолжал собираться и публиковаться сам.
> Читай раздел 1 и 3 целиком, дальше — только нужный рецепт.

---

## 1. Как устроен сайт — одна минута

- Контент живёт в **модулях канона: `src/content/*.ts`**. Это
  «база данных» сайта, разбитая по темам: книги — `books.ts`,
  персонажи — `characters.ts`, корпорации и фракции — `corporations.ts`,
  досье — `dossier.ts`, мир и техника — `world.ts`, импланты —
  `implants.ts`, оружие — `weapons.ts` и `weapon-specs.ts`, хроники —
  `chronicles.ts`, таймлайн — `timeline.ts`, фрагменты — `excerpts.ts`,
  галерея — `gallery.ts`, синопсис — `synopsis.ts`, суть истории —
  `story.ts`, главная (маркиза, блоки) — `home.ts`, общее
  (акценты, пути к картинкам) — `shared.ts`.
  Страницы — шаблоны, которые сами рисуют всё, что найдут в данных.
- `src/lib/content.ts` — точка входа: только ре-экспорты модулей,
  его править не нужно.
- Добавил запись в модуль канона → на сайте появилась карточка,
  страница, пункт поиска и строчка в карте сайта. **Никакой
  другой код править не нужно.**
- Правка текста = правка текста в кавычках. Это безопасно.
- Структура (запятые, скобки, кавычки) = код. Аккуратность важна.

## 2. Три команды работы

```bash
# 1. Посмотреть локально (http://localhost:3000/History-of-Daro/)
npm run dev

# 2. Проверить, что ничего не сломалось (то же сделает GitHub сам)
npm run build:static

# 3. Опубликовать
git add -A && git commit -m "content: добавлен персонаж N" && git push
```

После пуша GitHub сам пересоберёт сайт за ~3 минуты и опубликует.
Если сборка покраснела — письмо от GitHub придёт на почту, а
подсказка что не так — в конце этого гайда (раздел «Если сломалось»).

## 3. Золотые правила

1. **Ничего не удалять** — только дополнять. Старые записи не мешают.
2. **`slug` / `id` — латиницей**, без пробелов, уникально. Именно он
   становится адресом страницы (`/excerpts/holodnyj-start`).
3. **Каждая запись — через запятую** от соседней. Закрывающая `},`
   обязательна.
4. **Кавычки внутри текста** — если внутри текста нужны кавычки,
   используй «ёлочки» — они не ломают синтаксис.
5. **Картинки** кладутся в `public/…` и пишутся как
   `asset("/covers/…")` или `asset("/img/chars/…")` — со словом
   `asset(...)` и без него не заработает basePath на GitHub Pages.
6. **Не трогай**: папку `src/components` (эффекты и движки),
   `src/lib/audio-*.ts`, `src/lib/sfx.ts`, `.github/`, `next.config.*`.
   Это несущая конструкция.
7. Сомневаешься — запусти `npm run build:static` перед пушем.

## 4. Мини-словарь (встречается всюду)

| Поле | Что значит | Значения |
|---|---|---|
| `accent` | цвет карточки | `"cyan"` / `"magenta"` / `"amber"` |
| `tag` | короткая метка-капсула | «ДОСЬЕ», «ИМПЛАНТ», «ГРУППА»… |
| `role` | строка-подзаголовок | «охотник за долгами» |
| `stats` | шкалы карточки | `{ label: "Сила", value: 8 }` — value 0–10 |
| `side` | фильтр персонажей | `"resistance"` / `"corps"` / `"outside"` |

## 5. Рецепты

### 5.1 Добавить персонажа (раздел «Персонажи»)

Файл `src/content/characters.ts`, массив `CHARACTERS`. Вставь в конец
массива (перед закрывающей `];`), не забув запятую после предыдущей
записи:

```ts
{
  id: "imya-personazha",            // латиницей, уникально
  name: "Имя Фамилия",
  tag: "ДОСЬЕ",                     // метка-капсула
  role: "кто он в Хи-Мигате",
  text: "2–4 предложения: чем известен, почему опасен, чего хочет.",
  stats: [                          // по желанию; value 0–10
    { label: "Влияние", value: 6 },
    { label: "Опасность", value: 9 },
    { label: "Связи", value: 4 },
  ],
  quote: "Одна фраза-визитка персонажа.",
  accent: "cyan",                   // cyan | magenta | amber
  portrait: asset("/img/chars/imya.webp"), // положи картинку в public/img/chars/
  side: "resistance",               // resistance | corps | outside
},
```

Файл без `portrait` — карточка покажется с заглушкой; без `stats`
и `quote` — тоже допустимо.

### 5.2 Добавить имплант

Это тот же формат, что персонаж, но массив называется `IMPLANTS`:

```ts
{
  id: "nazvanie-implanta",
  name: "Название импланта",
  tag: "ИМПЛАНТ",
  role: "производитель · класс",
  text: "Что делает, чем платят за установку, чем опасен.",
  stats: [
    { label: "Мощность", value: 7 },
    { label: "Риск отторжения", value: 5 },
  ],
  quote: "Рекламный слоган или отзыв носителя.",
  accent: "magenta",
},
```

### 5.3 Добавить корпорацию

Корпорация состоит из **двух** записей (данные + файл в досье мира).
Она появится **сразу в двух местах**: на странице «Организации и
корпорации» (`/corporations`) и в досье мира (`/world`).

**Шаг 1** — массив `CORPORATIONS` (страница «Корпорации»):

```ts
{
  id: "nazvanie",                   // латиницей; используется corpFile
  name: "«НАЗВАНИЕ»",
  tag: "КОРПОРАЦИЯ · СЕКТОР",
  role: "чем владеет в Хи-Мигате",
  text: "3–5 предложений: сфера, методы, конфликт, тайна.",
  accent: "amber",
},
```

Текст `text` — то, что откроется в корпоративном файле на
`/corporations` (карточка + досье-панель с монограммой).

**Шаг 2** — массив `DOSSIER_FILES`, файл досье для страницы «Мир»:

```ts
corpFile(
  "nazvanie",                       // ТЕПЕРЬ ЖЕ id, что и в CORPORATIONS
  "статус файла",                   // например: «Активен», «Под наблюдением»
  8,                                // угроза 0–10
  "оценка угрозы словами",          // подпись к шкале
  [
    "актив №1",                     // чем владеет / чем известна
    "актив №2",
  ],
  { speaker: "ИСКИНА", text: "реплика перехвата внутреннего канала" },
),
```

**Необязательно** — перекрёстные ссылки в досье на
`/corporations` живут в файле `src/components/corporation-registry.tsx`,
словарь `CORP_LINKS` (ключ — тот же `id`). Добавишь строку — в файле
новой корпорации появятся кнопки-ссылки. Без строки там всё равно
будет ссылка «Досье мира».

### 5.4 Добавить фракцию (не корпорацию)

Массив `FACTIONS` — формат как у корпорации без шага 2:

```ts
{
  id: "imya-frakcii",
  name: "«ФРАКЦИЯ»",
  tag: "ГРУППИРОВКА · РАЙОН",
  role: "чем занимается",
  text: "2–4 предложения.",
  accent: "cyan",
  outside: true,        // необязательно
},
```

**Флаг `outside: true`** добавляет фракцию в блок «Сопротивление
и независимые» на странице `/corporations` (массив
`RESISTANCE_GROUPS` собирается из помеченных автоматически).
Без флага фракция видна только на `/world`. Полные файлы групп
всегда лежат в досье мира; на странице корпораций — сводка.

**Необязательно** — ссылки «Смежные файлы» на её карточке живут
в `src/components/resistance-grid.tsx`, словарь `RESISTANCE_LINKS`
(ключ — тот же `id`). Без строки карточка просто без ссылок.

**Необязательно** — строка перехвата на карточке: поле `log` у
фракции — `{ speaker: "ИСТОЧНИК", text: "одна строка эфира" }`.
Без поля блока перехвата нет.

### 5.5 Добавить оружие

Массив `WEAPONS`:

```ts
{
  id: "nazvanie-oruzhiya",
  name: "Название",
  tag: "СТВОЛ · КЛАСС",
  role: "производитель",
  text: "Как работает, кому выдаётся, чем примечательно.",
  stats: [
    { label: "Урон", value: 8 },
    { label: "Точность", value: 6 },
    { label: "Доступность", value: 3 },
  ],
  quote: "Реплика владельца.",
  accent: "amber",
  side: "corporate",                // corporate | resistance
},
```

**Канон-каталог «Оружие и владельцы»** — отдельный массив
`WEAPON_SPECS` (рядом с `WEAPONS`): привязка оружия к владельцу,
параметры (длина/вес/заряд/дальность), звук, свет, режимы стрельбы.
Запись попадает на `/armory` в свою подгруппу сама (поле `group`:
«Холодное» / «Луки Лины» / «Огнестрельное» / «Тяжёлое», порядок
подгрупп — `WEAPON_SPEC_GROUPS`) и в поиск. Служебные заметки
художнику (референсы, «что рисовать») сюда не вносятся — это
публичная выжимка канона. Если оружие есть в обоих массивах,
следи, чтобы описания не противоречили друг другу.

### 5.6 Добавить технологию или аномалию

Массивы `TECH` и `ANOMALIES` (одинаковый формат):

```ts
{
  id: "nazvanie",
  name: "Название",
  tag: "ТЕХНОЛОГИЯ",                // или «АНОМАЛИЯ»
  role: "кто использует",
  text: "2–4 предложения: принцип, цена использования, слухи.",
  accent: "cyan",
},
```

### 5.7 Добавить событие таймлайна

Массив `TIMELINE`. Эры уже заведены: `pred` (предыстория),
`t1` (после тома I), `t2` (после тома II), `t3` (том III).

```ts
{
  id: "event-id",                   // латиницей, уникально
  era: "t1",                        // pred | t1 | t2 | t3
  when: "2147 · март",              // как показывать дату
  title: "Название события",
  text: "1–3 предложения: что произошло и чем аукнулось.",
  accent: "magenta",
  // classified: true,              // раскомментируй для «засекреченного»
},
```

Порядок в массиве = порядок на странице (внутри эры).

### 5.8 Добавить фрагмент тома (читалка)

Массив `EXCERPTS`. Фрагмент автоматически получит страницу
`/excerpts/<slug>`, попадёт в поиск и sitemap. Страницы томов
(`generateStaticParams`) подхватят его сами.

```ts
{
  slug: "nazvanie-fragmenta",       // станет адресом страницы
  bookSlug: "tom-1",                // slug тома из BOOKS
  label: "Эпизод 02",               // метка на карточке
  title: "Название фрагмента",
  accent: "cyan",
  place: "Хи-Мигата · ярус 12",
  time: "2147 · апрель",
  status: "Расшифровано",           // статус выгрузки
  lead: "1–2 предложения-крючок, видимы до чтения.",
  tags: ["метка1", "метка2"],
  sections: [                       // секции текста; их сколько нужно
    {
      title: "Заголовок секции",    // можно опустить (title?: ...)
      paragraphs: [
        "Первый абзац.",
        "Второй абзац.",
      ],
      // log — реплики «терминала», по желанию:
      log: [
        { speaker: "ИСКИНА", text: "реплика системы" },
      ],
    },
  ],
  terminalQuote: {
    text: "Цитата в терминале в конце",
    source: "ОТКУДА · ИСТОЧНИК",
  },
  // note: "Примечание автора под фрагментом.",
},
```

### 5.9 Добавить хронику (архив)

Массив `CHRONICLES` — получит страницу `/chronicles/<slug>`:

```ts
{
  slug: "imya-hroniki",
  code: "ХР-02",
  title: "Название",
  subtitle: "Подзаголовок",
  status: "Восстановлено",
  accent: "amber",
  sourceLabel: "источник записи",   // «бортовой самописец», «журнал»…
  tags: ["метки"],
  lead: "Крючок для карточки.",
  intro: ["Вводные абзацы."],
  scenes: [
    {
      title: "Сцена 1",
      paragraphs: ["Текст сцены."],
      log: [{ speaker: "ГОЛОС", text: "реплика" }],
    },
  ],
  outro: "Финальная строка.",
  related: [                        // ссылки на другие разделы сайта
    { label: "Персонаж", href: "/characters", note: "почему связан" },
  ],
  terminalQuote: { text: "Цитата", source: "ИСТОЧНИК" },
  // cover: asset("/img/chron/imya.webp"),  // широкий кадр сцены
},
```

`href` в `related` — только существующие разделы: `/`, `/books`,
`/world`, `/characters`, `/armory`, `/implants`, `/chronicles`,
`/story`, `/author`, `/timeline`, `/excerpts`. Линтер проверит.

### 5.10 Короткие заметки (без структуры)

- `DAILY_LIFE` — карточки «как живут» на «Мире»:
  `{ title: "...", text: "...", accent: "cyan" }`
- `HUMAN_STORIES` — человеческие истории на «Сути»:
  `{ title: "...", text: "...", accent: "amber" }`
- `MARQUEE_ITEMS` — бегущая строка в шапке: `"ТЕКСТ ·"`
- `WORLD_STATS` — цифры мира: `{ to: 7, suffix: "", group: true, label: "корпораций" }`
- `INFLUENCES` — «на что вдохновлён»: `{ source: "…", taken: "…" }`
- `PRINCIPLES` — принципы цикла: `{ title: "…", text: "…" }`

### 5.11 Добавить книгу/том (осторожно)

Массив `BOOKS` — самая «тяжёлая» запись: slug, volume, title,
status, accent, cover (`asset("/covers/…")`), pages, tags, logline,
synopsis (абзацы), acts, facts, terminalQuote. Копируй целиком
существующий том и меняй содержимое. Новая страница тома требует
ещё и папку `src/app/books/<slug>/page.tsx` (копия tom-1 с другим
индексом BOOKS[3]) — это уже «код», но копипаста. И обнови
`scripts/make-og.py` (ROMAN/SOURCE) — либо попроси помощи.

### 5.12 Добавить арт в галерею

Массив `GALLERY` (`src/content/gallery.ts`). Сначала положи файл в
`public/img/scenes/`, `public/img/chars/` или `public/covers/`
(webp/png, до ~500 КБ), потом добавь запись:

```ts
{
  id: "art-moe-nazvanie",           // латиницей, с префикса art-
  src: asset("/img/scenes/file.webp"), // тот же путь, что в public/
  title: "Название записи",
  kind: "СЦЕНА",                    // СЦЕНА | ПОРТРЕТ | ОБЛОЖКА
  caption: "1–2 предложения из канона.", // подпись под артом
  accent: "cyan",
},
```

Запись появится на `/gallery` сама — в сетке, фильтре («Сцены» /
«Портреты» / «Обложки») и в счётчиках. Пропорции рамки зависят
от `kind`: сцены 16:10, портреты 3:4, обложки 2:3 — выбирай
ближайший, картинка обрежется по центру. Лишний арт = удалить
блок записи из `GALLERY` (сам файл в `public/` можно оставить).

### 5.13 Обновить синопсис, логлайн или темы цикла

Канон-тексты цикла живут в `src/content/synopsis.ts` (синопсис,
логлайн, темы, принципы) и `src/content/story.ts`
(`HUMAN_STORIES`, `INFLUENCES`):

- `SYNOPSIS_FULL` — полный синопсис «Проекта Восход» (массив
  абзацев, дословно текст автора);
- `SYNOPSIS_SHORT` — краткий анонс (3 абзаца, дословно);
- `LOGLINE` — одна строка-логлайн;
- `THEMES` — темы цикла: `{ title, text }`.

Где показываются сами:
- `/story` — секция 01 «Синопсис»: логлайн + полный синопсис +
  карточки тем;
- `/books` — блок «Анонс цикла» над списком томов.

Правила: текст менять дословно, без сокращений (это слова автора);
абзац = один элемент массива; если меняешь порядок или добавляешь
абзац — проверь `npm run build`. Больше нигде правки не нужны:
поиск и лендинг используют эти же константы.

### 5.14 Собрать главную из блоков

Данные главной — `src/content/home.ts`. Порядок массива
`HOMEPAGE_BLOCKS` = порядок секций на странице (между хрониками
и подпиской). Доступные виды блоков:

- `stats` — анимированные цифры из `WORLD_STATS` (`limit` — сколько
  первых показать);
- `timeline` — тизер таймлайна (засекреченные записи пропускаются);
- `arsenal` — карточки канон-каталога `WEAPON_SPECS` (опционально
  `group`: «Холодное», «Луки Лины», «Огнестрельное», «Тяжёлое»);
- `quote` — цитата дословно (`text`, `source`);
- `links` — плитки-ссылки (`items`: `href`, `title`, `text`, `accent`).

У всех видов (кроме `quote`) есть `kicker`, `title`, `accent` и
необязательные `href` + `linkLabel` — ссылка «подробнее»; href
проверяется линтером контента. Убрать блок = удалить объект из
массива. Новый вид блока = новый шаблон в
`src/components/home-blocks.tsx` (это уже код — можно позвать
помощи).

### 5.15 Вести календарь событий мира

Данные — `src/content/calendar.ts`, массив `CALENDAR_EVENTS`;
показывается на `/timeline` (секция 02 «Календарь событий мира»).
Сортировка по `when` и группировка по месяцам — автоматические.

Шаблон записи:

```ts
{
  when: "2147-03-30",      // ISO-дата «ГГГГ-ММ-ДД»: порядок и месяц
  dateLabel: "30 марта",   // подпись на карточке
  title: "Проект «Восход»: закрытая сессия",
  place: "резервный штаб, уровень минус семь",
  text: "Одно-два предложения: что произошло и чем это слышно в городе.",
  accent: "cyan",          // cyan | magenta | amber
  href: "/story",          // необязательно; проверяется линтером
  hrefLabel: "Проект Восход",
},
```

- Даты сейчас **примерные** — шаблон по решению от 2026-11-02.
  Когда придут канонические, меняй `when` и `dateLabel`, остальное не
  трогай: месяц для группировки берётся из `when`.
- Плашка «даты примерные» над календарём — текст `CALENDAR_NOTE` в
  том же файле; когда даты станут каноническими, её можно убрать
  (удалить абзац с ней в `src/components/calendar-view.tsx` или
  позвать помощи).
- Событие никуда не ведёт — оставь `href`/`hrefLabel` пустыми.
- Новый месяц появится сам, как только в нём окажется первое событие.

## 6. Если сломалось

1. **Письмо «Deploy failed»** — открой лог (ссылка в письме),
   самая частая причина: пропущенная запятая/скобка в модуле канона
   (`src/content/*.ts`).
   Строка с ошибкой будет видна в логе шага «Lint content» или
   «Build static site».
2. **Проверь локально**: `npm run build:static` — покажет то же самое.
3. **Откат**: `git revert HEAD` — отменяет последний коммит новым
   (история не портится), затем `git push`.
4. **Линтер контента** (`node scripts/check-content.mjs`) — проверяет
   слаги-дубли, несуществующие ссылки и sitemap. Запусти сам, если
   сомневаешься.
5. В крайнем случае — напиши мне в чат: разберём.

## 7. Что появляется само (руками делать не надо)

- страница `/excerpts/<slug>` и `/chronicles/<slug>`;
- карточка корпорации на `/corporations` — из массива `CORPORATIONS`;
- фракция с `outside: true` — в блоке «Сопротивление и независимые»
  на `/corporations` (массив `RESISTANCE_GROUPS` собирается сам);
- запись в `WEAPON_SPECS` — карточка на `/armory` в своей подгруппе
  (`group` + порядок `WEAPON_SPEC_GROUPS`) и в поиске;
- арт из `GALLERY` — на `/gallery`: сетка, фильтр и счётчики типов;
- запись в поиске (Ctrl+K);
- строка в sitemap.xml — но проверь, что маршрут внесён в
  `src/app/sitemap.ts` (список там ручной; линтер подскажет, если
  забыл);
- OG-картинка у томов: пересобери `python3 scripts/make-og.py`
  после изменения обложки/названия/логлайна тома.
