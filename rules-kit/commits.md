# Commits — стиль коммитов и git-дисциплина

История коммитов — это журнал решений проекта. По логу должно быть
понятно, что изменилось, зачем и чем проверено — без открытия диффа.

---

## 1. Формат сообщения

```
<тема>: <что сделано>; <существенная деталь>; <чем проверено>
```

- Первая буква строчная, язык русский, без точки в конце.
- Секции разделяются «;» — читать легче, чем простыню.
- «Чем проверено» обязательно для кода и контента: имя скрипта,
  количество проверенных маршрутов, «CI success».
- Хеш коммита в теле сообщения не пишется (сам на себя не ссылается);
  на чужие коммиты ссылаться можно и нужно, когда чанк закрывает
  чужой хвост.

## 2. Темы (префиксы)

Стартовый набор; список живёт в этом файле и растёт по мере проекта:

| Префикс | Для чего |
|---|---|
| `вёрстка:` | HTML/CSS страниц, разметка, адаптив |
| `дизайн:` | визуальный язык, палитра, эффекты |
| `контент:` | тексты, копирайт, стоп-лист |
| `скрипт:` | скрипты проверок и генерации |
| `инфра:` | CI, деплой, gitignore, настройки репо |
| `a11y:` | доступность |
| `фикс:` | точечные багфиксы |
| `метафайл:` | SESSIONS/BACKLOG/PROJECT-META, правила |

Один коммит не смешивает темы: правка текста + скрипт проверки к ней —
два коммита, скрипт первым.

## 3. Примеры (хорошие)

```
контент: страница «О проекте» — блок команды переписан с перечисления
ролей на конкретику (имена, годы, цифры); стоп-лист +«уникальный путь»;
check-slop.py 0 находок

a11y: контраст приглушённых подписей поднят white/35 → white/60,
aria-label кнопки меню согласован с видимым текстом; axe: 0 нарушений
на 12 страницах

метафайл: SESSIONS — итоги сессии (редизайн шапки, деплой), хвост
«мобильное меню» перенесён в BACKLOG с причиной

вёрстка: шапка — 4 ссылки + кнопка «Галерея» с разделителем, панель
«Ещё» 2×2; overflow 0px на 360/768/1024/1280/1920 (verify-nav)
```

## 4. Примеры (плохие — так не надо)

- `правки` — не понятно ни что, ни зачем;
- `фикс бага с меню + заодно обновил правила и почистил картинки` —
  три причины в одном коммите;
- `feat: implement responsive navigation system with enhanced UX` —
  английский сленг и вода вместо фактов;
- `wip` — черновик не коммитится, чанк закрывается целиком.

## 5. Дисциплина

1. **1 коммит = 1 причина.** Мелкие чанки: один фикс / одна страница /
   один раздел метафайла. Незапушенные коммиты не копить.
2. **Коммит → пуш → CI сразу.** Пайплайн перед коммитом обязателен
   (см. `ci-gates.md`); красный CI = чанк не закрыт.
3. **Force-push запрещён.** Если локальная история разошлась с
   `origin/main` — разобраться (fetch, log, diff), а не переписывать.
   Исключений нет: «потерянные» коммиты восстанавливаются из reflog,
   но доверие к истории не восстанавливается.
4. **Перед началом работы:** `git fetch origin && git status -sb &&
   git log --oneline -5`. Рабочая копия = зеркало GitHub; расхождение
   разбирается до правок, а не после.
5. **Правка только .md (метафайлы, правила)** — коммит сразу, без
   пайплайна. Пайплайн обязателен для кода, разметки и контента сайта.
6. **Автокоммиты инфраструктуры** (сообщение-UUID, «commit all»)
   до пуша не доживают: `git reset --soft` + осмысленное сообщение.
7. Метафайлы обновляются тем же чанком, что и изменение, если оно
   меняет «почему так» (решение, отключение, рецепт отката).
